# Portage v0.2 实现验收

当前浏览器原型展示体验。以下场景在真实服务端与适配器实现后验收。

## 核心闭环

- 从两个 CLI 来源登记真实 session，准确显示 provider、harness、host 和原生身份。
- 发送到指定 terminal session，原生记录可核对输入和来源，回读去重。
- 三个成员加入房间，指定 coordinator，用户消息先唤醒负责人。
- Coordinator 通过 MCP 联系成员，回传结果和文件并形成完整 trace。
- 房间可读范围与实际唤醒范围分别验证，每位接收方有独立结果。
- 全局和房间 MD 每次 query 按版本注入，展示内容快照和体积。
- 关闭通信、撤销权限、暂停房间和预算命中后，后续自动投递按规则 held。

## 故障与并发

- 接收提交前后崩溃，accepted 对应 Message、Delivery、Event 可恢复。
- 同请求重复返回同一逻辑结果，正文冲突明确报错。
- 群消息部分离线时其他成员继续接收。
- 原生提交后失联进入 uncertain，回读或原生幂等能力核对。
- 切换会话和重连后旧 epoch 项重新检查，两个入口共享原生输入锁。
- 配置发布与发送并发，记录接收与实际 dispatch 的规则版本。
- 原生回显、重读和断线补读去重，日志缺口可见。

## 协作频率

- mentions、coordinator、all、manual 的分发与唤醒符合定义。
- 短时间消息合并唤醒，原消息和回执保留。
- 状态和回执按配置更新视图，自动唤醒有明确触发。
- 消息速率、轮次、并发、trace 和成员对预算可执行、可解释、可恢复。
- collaboration.md 发布后，下一次检查或 query 使用对应新版本。

## 管理与产物

- Session CRUD 按能力开放并显示原生效果。
- 消息修订保留已投递版本，更正方式可追溯。
- 本地删除与原生删除分别显示结果。
- 文件、图片、JSON、文本保留来源和版本，按权限访问。
- 两台设备材料化文件后核对 hash。
- 同一 session 多房间共享上下文事实可见，可创建独立原生 session。

## UI 与性能

- 来源树符合 Provider → App / VS Code CLI / Terminal → Session。
- 拖入和选择器均可添加成员，关键操作可用键盘。
- 房间、对话和信息流共用事件，消息可定位 trace 和原生凭据。
- 未唤醒、工作中、待用户、排队、预算、关闭、离线、未知有文字区分。
- 按 ARCHITECTURE.md 的载荷测延迟、吞吐、内存、画布和长时间运行。

逐项扩展 App / IDE bridge、多设备、多用户和企业聊天 gateway，记录支持版本、验证结果和降级行为。
