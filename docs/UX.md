# Portage UX v1.0

2026-11-17 冻结。交互原型为 `demos/portage-ux-demo.html`，所有 session、消息和投递均为模拟。

## 信息架构

| 区域 | 内容与操作 |
| --- | --- |
| 左侧来源树 | Provider → App / VS Code CLI / Terminal → Session，搜索、选择、开关和拖入房间 |
| 左侧房间列表 | 房间名称、成员数、暂停状态，新建与进入 |
| 中央主区 | 房间、对话、信息流三种视图 |
| 右侧检查器 | 成员、统筹者指定、收件箱队列、消息投递、规则版本与产物 |
| 输入区 | 实际目标、正文、附件及发送 |
| 信息流 | 结构化时间线 + Trace 图 + 投递板 |

## 来源树与房间成员

拖入或「添加成员」加入房间。成员详情提供 **退出房间**：确认后移出活动工位，来源树中的原生 session 仍在。session 可属于多个房间。

## 房间视图与模式连线

顶部模式切换：

| 模式 | 工位连线 | 说明 |
| --- | --- | --- |
| 统筹 | 从唯一统筹者指向其他成员的派发线 | 成员详情「设为统筹者」；改任后连线中心切换 |
| Swarm | 无成员间固定连线 | 仅在实际投递时显示运动粒子 |
| 仅 @ / 手动 | 无固定派发线 | 唤醒范围更窄 |

工位展示 session 名称与来源，**不展示工种角色标签**。统筹者模式在工位上标「统筹」仅表示路由中心。工作、未唤醒、排队、关闭和预算等待有各自视觉反馈。位置保持稳定。

## 对话与收件箱

消息显示来源、目标、时间、附件和每位接收方状态。Session 检查器「收件箱」列出该成员排队 / held 的 Delivery，含等待原因；就绪后按序投递。

## 信息流（v1 结构）

不再只用散乱事件条，主区分为：

1. **时间线**：按时间排列的结构化事件（用户发送 / 排队 / 提交 / 回复 / 预算等待），可筛选房间与 trace  
2. **Trace 图**：节点为用户与成员，边为显式因果；点击高亮时间线对应项  
3. **投递板**：当前 queued / held / submitted 计数与明细  

运动粒子表达在途投递；已完成链路保留细线。推断关系虚线标注 inferred。

## 状态文案

| 文字状态 | 含义 |
| --- | --- |
| 工作中 | 宿主报告 running |
| 未唤醒 | 可读但未被唤醒 |
| 等待投递 | Inbox 中有 queued/held |
| 待你处理 | 原生等待用户 |
| 通信关闭 | 收发与自动唤醒已关闭 |
| 预算等待 | 轮次或速率预算命中 |
| 只读连接 | 当前入口只读 |
| 状态未知 | 信号缺失或过期 |

房间摘要展示 `rounds/roundBudget` 自动轮次，例如 `2/4`。

## 沟通预算面板

展示模式、自动轮次、消息速率、活跃席位。命中后显示原因与恢复操作。

## 原型范围

原型覆盖：来源分组、加入/退出、统筹/Swarm 连线切换、直接聊天、房间消息、附件、暂停/恢复、MD 编辑、收件箱排队、结构化信息流与检查器。刷新恢复示例数据。
