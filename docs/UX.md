# Portage UX v1.0

2026-11-17 冻结。交互原型为 `demos/portage-ux-demo.html`，所有 session、消息和投递均为模拟。

## 信息架构

| 区域 | 内容与操作 |
| --- | --- |
| 左侧来源树 | Provider → App / VS Code CLI / Terminal → Session，搜索、选择、开关和拖入房间 |
| 左侧房间列表 | 房间名称、成员数、暂停状态，新建与进入 |
| 中央主区 | 房间、对话、信息流三种视图 |
| 右侧检查器 | 房间概览、成员详情、待送达队列、送达情况、协作约定版本与共享文件；技术字段折叠在「Technical details」里 |
| 输入区 | 实际目标、正文、附件及发送 |
| 信息流 | 结构化时间线 + Trace 图 + 投递板 |

## 视觉语言

温暖、安静、像一间有人在的工作室：

- 暖白底（`--paper`）+ 浅灰圆角卡片（`--card`，16–24px 圆角）+ 柔阴影；主操作是黑色胶囊按钮，次操作是白色胶囊
- 系统字体（SF / Segoe UI），正文 14px，最小字号 11px；等宽字体只用于代码、ID、hash 与快捷键
- 界面文案为英文：短句直接说「发生了什么、你能做什么」，单复数随数量变化（1 member / 3 members）；截断按行数由 CSS 控制，不按字符数
- 成员是一只深色圆头小角色：会眨眼、呼吸，围巾颜色就是该成员的身份色（同色出现在 @ 标签、链路图节点与连线）；未唤醒时闭眼并飘起 z
- 状态用柔和的语义色：绿色 = 已送达 / 就绪，琥珀 = 排队 / 暂缓 / 待核对，砖红 = 失败；不用高饱和警示色
- 空房间、空对话、没找到会话时给出小角色 + 一两步可点击的下一步，而不是空白

## 来源树与房间成员

拖入或「Add member」加入房间。成员详情提供 **退出房间**：确认后移出活动工位，来源树中的原生 session 仍在。session 可属于多个房间。

## 房间视图与模式连线

顶部模式切换：

| 模式 | 工位连线 | 说明 |
| --- | --- | --- |
| 统筹 | 从唯一统筹者指向其他成员的派发线 | 成员详情「Make lead」；改任后连线中心切换 |
| 自由协作（Swarm） | 无成员间固定连线 | 仅在实际投递时显示运动粒子 |
| 仅 @ 提及 / 手动 | 无固定派发线 | 唤醒范围更窄 |

工位展示 session 名称与来源，**不展示工种角色标签**。统筹者模式在工位上标「Lead」仅表示路由中心。工作、就绪、未唤醒、待送、关闭和额度等待有各自视觉反馈。位置保持稳定。

## 对话与收件箱

消息显示来源、目标、时间、附件和每位接收方状态。Session 检查器「Waiting to deliver」列出该成员排队 / held 的 Delivery，含等待原因；就绪后按序投递。

## 信息流（v1 结构）

不再只用散乱事件条，主区分为：

1. **时间线**：按时间排列的结构化事件（你发送 / 排队 / 送达 / 回复 / 额度等待），可按链路筛选（选项以链路第一条消息命名）  
2. **链路图**：节点为你与成员，边为显式因果；点击高亮时间线对应项  
3. **收件箱**：排队中 / 暂缓 / 已送达 / 待核对 计数与明细，并用一句话说明当前是否有东西卡住  

运动粒子表达在途投递；已完成链路保留细线。推断关系虚线标注 inferred：消息的因果父来自另一成员、但这次回应没有反向 Delivery 时，画一条从回应者指向父消息发送者的虚线。

## 状态文案

| 文字状态 | 含义 |
| --- | --- |
| Working | 宿主报告 running |
| Ready | 空闲，有新消息会被自动唤醒 |
| Asleep | 可读但未被唤醒 |
| Needs you | 原生等待用户 |
| Muted | 收发与自动唤醒已关闭 |
| Offline | 会话不在线 |
| Unknown | 信号缺失或过期 |

排队与额度等待不是成员状态，而是工位上的附加标签（「N queued」「N unread」）和逐条暂缓原因。

舞台左上角的房间牌显示房间名、一句话状态（「3 members · all ready」）和近 12 分钟的动静曲线。舞台下方的摘要显示 working / asleep / queued / unread；「seats full」「rounds used」只在命中时出现。自动轮次 `2/4` 与同时工作 `running/max_concurrent` 常驻在右侧「Auto-collaboration limits」。

有成员处于「Needs you」时，房间顶部出现提醒条（View / Reply），工位亮起紫色举手与脉冲环，来源树对应圆点闪动。

暂缓原因逐条有文字：等就绪、房间暂停、通信关闭、限速（附「continues in Ns」倒计时）、轮次上限、唤醒上限、等席位、结果不明（回读核对中）、被占用（附占用会话的进程）、待确认身份、权限变化、超出上下文上限。排队与暂缓中的投递可在会话详情或消息链路里取消；改绑原生身份后详情给出「Confirm new identity」。

原生回合失败等宿主说明显示在工位下方与会话详情中。

## 自动协作额度

展示自动讨论轮次、近 1 分钟 AI 消息、同时工作（逐格点亮）、当前链路唤醒次数。命中后显示原因与恢复操作。

## 房间舞台

- 工位：工作中的成员亮起台灯与地面暖光；收件箱有待投递时桌上叠放纸张（暂缓为琥珀色）
- 在途投递是一封沿路径飞行的信（产物带折角），落地有双层涟漪；统筹模式的派发连线向成员方向流动
- 顶部行成员的发言气泡向房间中心侧向弹出，不越出舞台；你的发言气泡从门口向右侧空地弹出，不遮挡底排工位
- 「Delivered / Read」标签落在显示器旁，不压住工位名称；任何窗口尺寸下气泡、标签、工位与房间牌 / 添加位 / 门口互不遮挡
- 窗外有缓慢移动的光与云；`prefers-reduced-motion` 时全部静止（系统设置变化即时生效）
- 图例随模式出现：统筹模式下显示「Dispatch route」虚线；信息流图例区分实线（显式投递）与虚线（推断回应）
- 画布只在有运动时绘制：静止房间不耗帧，页面隐藏时停绘

## 对话

- `@别名` 渲染为成员色标签，点击打开该成员
- 回复显示被回应消息的引用；同一发送者连续消息合并展示
- 每条消息下逐接收方显示凭据标签：等待（含原因）/ Delivered / unread / Read；「Delivery」「Hide」只在悬停或聚焦时出现
- 空房间给出可点击的开场建议
- 历史只先加载最近一段，顶部「Load earlier messages」按页补读，补读时阅读位置不跳动
- 与某个会话对话时可切换「Portage messages / Its own record」：原生记录是该会话自己的输入、输出与回合边界，只读回读；输入以原始消息为标题、完整 query 可展开，并标注关联强度（From Portage · confirmed / Likely from Portage / Typed in its own app）；顶部显示同步时间或回读缺口
- 送达凭据阶梯：Delivered → In its record（原生回合会话）→ Read（接入 MCP 的会话）；详情先用一句话讲清（「Delivered to its session at 10:45; its own record confirmed it at 10:45; it read it at 10:46.」），适配器、epoch、hash 等折叠在技术细节里

## 写消息

输入框下方实时显示「Wakes / Wakes nobody」及原因，规则与 Bus 一致：手动模式不唤醒；@ 优先；统筹模式先到统筹者；自由协作 / 仅 @ 提及 无 @ 时只写入历史。

## 登记会话

登记会话时，每个候选标明投递方式（原生回合可自动唤醒 / 文件收件箱经 MCP 读取）、是否正被交互式进程占用、工作目录与最近活跃时间。

## 命令面板

`⌘K` 打开：模糊搜索房间、会话（含别名与原生身份）、视图与操作（Watch a demo、暂停/恢复、Edit room rules / global rules、Preview what they receive、Find local sessions、Add members、New room）。`↑↓` 选择，`↵` 执行。`1/2/3` 切换视图，`/` 写消息。

## 协作约定

编辑 collaboration.md 时实时校验 YAML 策略头（与服务端同一解析器），显示将执行的策略或全部错误，非法时禁止发布。「Insert policy header」把当前策略写进文档、随版本保存。

## 原型范围

原型覆盖：来源分组、加入/退出、统筹/Swarm 连线切换、直接聊天、房间消息、附件、暂停/恢复、MD 编辑、收件箱排队、结构化信息流与检查器。刷新恢复示例数据。
