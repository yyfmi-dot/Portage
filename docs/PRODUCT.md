# Portage 产品设计 v1.0

2026-11-17 冻结。本文件与 ARCHITECTURE / DOMAIN / UX / MVP 及 `demos/portage-ux-demo.html` 共同构成第一版定稿。本地 Daemon、Codex / Claude Code 原生回合适配器、FileInbox 适配器、MCP 桥接、正式 UI 与会话标题双向同步已实现；默认数值可按实测调整，产品边界与对象语义不再随讨论漂移。

## 产品体验

用户打开 Portage，首先看到各个来源的原生 session。按 Codex、Claude 等提供方分组，再按 App、VS Code CLI、Terminal 等入口分组。每段原生会话有可辨识名称、来源、连接状态、运行状态与通信开关。

用户可以直接与某个 session 对话，也可以把几个 session 加入房间。成员可以随时退出房间；退出后不再接收该房间新的自动唤醒，历史按成员策略保留。来自不同工具的 agent 可以在授权范围内互相发现、联系、读取消息和共享产物。

Portage 承担通信与会话管理。具体模型调用、推理和工具执行由接入的原生运行环境完成。负责人 agent 可以根据消息作出分工，通过 Portage 执行信息传递。

## v1 冻结决策

| 议题 | 决定 |
| --- | --- |
| 架构是否够用 | 是。v1 做跨原生 session 的传信、房间、策略、投递与可观测；不做 ACP/A2A 协议运行时，也不做工作流编排器 |
| 房间角色 | **不做工种角色**。只保留统筹者作为唤醒/连线路由；分工说明仅作约束与指导，不干涉模型已有角色与正在干的活 |
| 加入 / 退出 | 支持。加入建立 Membership；退出写 `leftAt`，移出活动成员，停止该房间新的自动 Delivery；已有队列标 held/cancelled 并保留原因 |
| 协作拓扑 | 房间模式仅两种主形态：**统筹** 与 **Swarm**。可另选「仅 @」「手动」作为唤醒细项 |
| 统筹 | 房间有且仅有一位统筹者。用户发到房间时先唤醒统筹。房间视图画统筹 → 成员的派发连线 |
| Swarm | 无统筹拓扑。房间视图不画成员间固定连线；默认按 @ 唤醒，成员对等讨论 |
| 收件箱 | 会排队。每位接收 Session 独立 Inbox（持久 Delivery 队列），busy / 离线 / 预算等进入 queued 或 held |
| `2/4` 自动轮次 | 已用自动讨论轮次 / 上限。例如上限 4、当前 2：这条协作链上 agent 已自动往返 2 轮，还可自动 2 轮，到 4 后停止自动唤醒并等待用户 |
| 信息流 | v1 原型改为「结构化时间线 + Trace 图 + 投递状态」三栏式监控，事件可点回消息与原生凭据 |

## 核心使用场景

| 场景 | 用户操作 | 可见结果 |
| --- | --- | --- |
| 直接对话 | 选择一个已有 session 并发送 | 显示实际接收入口、排队和原生提交证据，回读对应记录 |
| Agent 互通 | 允许某 session 发现并联系授权 peer | Agent 通过 MCP 或其他接口收发，用户查看来源和去向 |
| 加入房间 | 拖入或选择添加 | Membership 生效，保留各自原生身份 |
| 退出房间 | 成员详情中退出，或房间管理移除 | 活动成员列表更新；历史按策略可读；新自动唤醒停止 |
| 统筹协作 | 模式设为统筹，指定唯一 coordinator | 派发连线；用户消息先到统筹，再由其联系成员 |
| Swarm 讨论 | 模式设为 Swarm | 无派发连线；按 @ 或手动唤醒对等协作 |
| 授权配置 | 用户或受委派 agent 改权限、统筹者、规则 | 管理 API 按调用者权限执行，版本可查 |
| 关闭通信 | disable 某个 session | 新的收发及自动唤醒停止，已有待投递项显示 held 原因 |
| 查看过程 | 进入信息流 | 时间线、Trace、逐接收方投递状态同屏可读 |

## 对话、房间与范围

私聊是用户或身份与一个目标的 conversation。房间是多成员 conversation。Thread 是房间内一个主题的讨论分支。

一个原生 session 可以加入多个房间，也可以从任一房间退出而不删除原生 session。Portage 对自身历史、附件和操作实施房间权限；原生宿主负责该 session 已有上下文。

第一版把 Room 和 Team 作为同一通信对象的两种产品表述。

## 权限、统筹者与规则文档

**不设房间工种角色**（实现 / 审查 / 设计等）。原生 session 自己的身份与正在干的活由宿主上下文决定，Portage 不覆盖、不改写。

v1 只保留通信所需的结构：

| 概念 | 作用 |
| --- | --- |
| 成员 Membership | 谁在房间里、读写与退出 |
| 统筹者（仅统筹模式） | 路由开关：谁先被唤醒、派发连线从谁画出；不是职业身份 |
| collaboration.md | **约束与指导**（何时联系谁、产物要带版本、别刷屏）；不是新的 system persona |

最高层全局 MD、工作区 MD、房间 collaboration.md 可按接收方编译进 query，篇幅保持短、可预览。注入内容不得要求模型「忘记」或替换其原生角色；只补充本房间的通信约定。

## 沟通频率

| 参数 | v1 默认 | 含义 |
| --- | --- | --- |
| 模式 | 新房间 Swarm（仅 @）；开发室示例为统筹 | 拓扑 + 默认唤醒 |
| 自动轮次上限 | 4 | 同一 trace 上 agent 自动互唤醒的最大轮数 |
| 每分钟 agent 消息 | 12 | 房间速率预算 |
| 自动活动席位 | 2 | 同时自动 running 的上限 |

达到限制时保留消息，显示可恢复的等待原因。用户可以暂停自动通信、唤醒一次、恢复或调整预算。

## 阶段边界

v1 交付：架构与产品定稿文档、UX 规范、可演示 HTML 原型。  
v1 实现目标：两个 CLI 来源 + 一个三成员房间的真实投递闭环（见 MVP.md）。  
后续：App / IDE bridge、多设备、多用户、企业聊天 gateway；可选把 A2A/ACP 作为一类 Endpoint，不替换原生 session 主路径。
