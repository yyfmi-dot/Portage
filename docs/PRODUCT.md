# Portage 产品设计 v0.2

2026-11-15 讨论稿。用户场景已经明确，本文记录本轮架构与交互的具体选择，供结合 HTML 原型继续讨论。可调默认值与阶段范围会随讨论更新。

## 产品体验

用户打开 Portage，首先看到各个来源的原生 session。按 Codex、Claude 等提供方分组，再按 App、VS Code CLI、Terminal 等入口分组。每段原生会话有可辨识名称、来源、连接状态、运行状态与通信开关。

用户可以直接与某个 session 对话，也可以把几个 session 拖入房间。房间拥有独立记录、主题、成员、角色、产物与 collaboration.md。来自不同工具的 agent 可以在授权范围内互相发现、联系、读取消息和共享产物。

Portage 承担通信与会话管理。具体模型调用、推理和工具执行由接入的原生运行环境完成。负责人 agent 可以根据消息作出分工，通过 Portage 执行信息传递。

## 核心使用场景

| 场景 | 用户操作 | 可见结果 |
| --- | --- | --- |
| 直接对话 | 选择一个已有 session 并发送 | 显示实际接收入口、排队和原生提交证据，回读对应记录 |
| Agent 互通 | 允许某 session 发现并联系授权 peer | Agent 通过 MCP 或其他接口收发，用户查看来源和去向 |
| 组成房间 | 多选或拖入 session | 成员加入共享 conversation，保留各自原生身份 |
| 统筹协作 | 指定 coordinator | 用户消息先投递给负责人，由其联系成员和汇总 |
| 开放讨论 | 选择 all 或按 mention 唤醒 | 授权成员读取讨论，每位成员独立排队与回执 |
| 授权配置 | 用户设置角色，或委派一个 agent 管理 | 实际管理操作按调用者权限执行，版本和修改者可查 |
| 关闭通信 | disable 某个 session | 新的收发及自动唤醒停止，已有待投递项显示 held 原因 |
| 原生产物传递 | 发送文件、图片、JSON 等 | 保留内容版本与来源，按目标能力送入原生会话 |
| 管理会话与历史 | 创建、重命名、归档、修订、删除 | 界面显示本地与原生的实际作用范围和部分结果 |
| 查看过程 | 进入房间或信息流 | 看见成员工作、未唤醒、排队、待用户、限流及消息因果链 |

## 对话、房间与范围

私聊是用户或身份与一个目标的 conversation。房间是多成员 conversation。Thread 是房间内一个主题的讨论分支，可以独立引用、过滤和订阅。

房间内定向给一个成员的消息仍属于该房间，其他授权成员可读。选择来源树中的 session 则进入私聊。UI 明确这两种作用范围。

一个原生 session 可以加入多个房间。Portage 对自身历史、附件和操作实施房间权限，原生宿主负责该 session 已有上下文。需要独立上下文的房间可以使用独立原生 session。

第一版把 Room 和 Team 作为同一通信对象的两种产品表述。多层组织和跨房间项目归属可以在实际需求明确后扩展。

## 角色、权限与规则文档

角色职责通过指令表达，例如统筹、实现、审查。读、写、邀请、管理角色、改规则和访问附件等权限由服务端执行。自然语言指令可以由被委派的 agent 转成管理 API 调用。

最高层全局 MD、工作区 MD、房间 collaboration.md、房间内角色说明按接收方编译进入每次 query。保留原始消息，记录注入的文档版本和内容快照。多跳转发使用原始内容引用，编译时只加入一遍适用规则。

规则发布后，权限和预算在下一次检查生效，正文在下一次原生输入生效。忙碌成员显示待下一轮应用。原生宿主要求 reload 的设置单独显示待原生重载。

## 沟通频率

MD 描述什么时候联系谁，Portage 执行唤醒与投递边界。用户可以选择 mentions、coordinator、all、manual，并调整合并提醒窗口、并发、消息速率、自动轮次和每条 trace 的唤醒预算。

达到限制时保留消息，显示可恢复的等待原因。状态与回执默认更新视图。用户可以暂停自动通信、唤醒一次、恢复或调整预算。

新房间建议默认 mentions，设置 coordinator 后可采用统筹模式。原型中的开发室预先配置为统筹模式。示例参数为每分钟 12 条 agent 消息、4 轮自动讨论、2 个自动活动席位，均为待讨论和实测的初始值。

## 原生同步与管理

“已接收”“已排队”“已写入”“已提交”“原生记录已确认”“agent 已确认处理”各自依据真实凭据显示。只读入口可以管理已获取的记录，写入和生命周期操作按适配器能力开放。

用户可以在 Portage 创建受管 session、恢复、重命名、归档和管理历史。创建原生 session、修改原生消息、删除原生历史等操作都需要对应适配器能力。界面清楚列出执行效果。

Portage 自有消息修订保持版本，已投递版本可追溯。原生支持编辑时调用原生能力，其他入口可以发送明确的更正消息。删除操作显示本地和原生作用范围。

## 其他实用用法

- 把一个 session 的分析结果定向给另一个 session 审查，保留所用文件版本及反馈链。
- Agent 忙时集中收取多条请求，下一次就绪时合并提醒，减少用户手动粘贴和反复唤醒。
- 关闭自动通信，保留房间记录，用户按需要手动唤醒某一位成员。
- 会话离线后继续保留队列与房间历史，重连时验证原生身份并恢复。
- 把产物分享给另一个授权房间，建立明确的来源引用和分发记录。
- 在企业群聊中 @ 常驻 bot，让结果返回原 thread，并在 Portage 查看设备侧 agent 的投递过程。

## 阶段与讨论重点

当前已有架构、领域、UX、验收文档和模拟 HTML 原型。真实服务、持久存储、适配器和多用户授权仍待实现。首个真实闭环建议从两个 CLI 来源和一个三成员房间验证，再逐项接入 App / IDE 和多设备。

需要结合原型继续讨论的选择包括房间与 Team 的表述、来源树的默认展开方式、唤醒默认值、最高层 MD 的体积与维护方式，以及首批真实接入来源。性能按架构文档的负载目标实测后调整。
